# Rule Language (closed vocabulary for the "Transformation rule" column)

Rules must be executable and identical in meaning for every developer. Write rules ONLY with the syntax and functions below. If you need something that is not here, add it to the `Assumptions` item of sheet `0_Header` as `Rule-language addition: NAME(args) = definition` and use it consistently.

## 0. Tool snippet caveat
The tool columns (SQL Server, Oracle, Informatica, Talend, Hop) are written from general product knowledge. They are starting points. Every function must be proven by the test case that exercises it (`TC-*` in sheet 6) before it is trusted. Where a tool has no single function, the cell says what to combine.

## 1. Mapping types (choose exactly one per target column)
| Type | Use when | Rule shape |
|---|---|---|
| DIRECT | Value copied, at most trimmed, same meaning and datatype | `COL = TRIM(SRC)` or `COL = SRC` |
| TRANSFORM | One source column, changed (cast, parse, reformat, case, sentinel to NULL, timezone) | `COL = TO_DATE(SRC,'YYYYMMDD')` |
| LOOKUP | Value translated through a reference table or dimension | `COL = LKP(REF_X, SRC -> target_value)` |
| DERIVE | Computed from two or more columns, or from conditions | `COL = CASE WHEN ... END` |
| CONSTANT | Fixed literal | `COL = 'MAIL02'` |
| SYSTEM | Generated by the ETL (surrogate key, batch id, load timestamp, hash) | `COL = NEXT_SEQUENCE(SEQ_X)` or `COL = :BATCH_ID` |
| SPLIT/MERGE | One source column to several targets, or several to one | `COL = SPLIT_PART(SRC,' ',1)` |
| NOT MAPPED | Target column intentionally has no source (needs a reason in Comments) | `n/a` |

Decision rule: pick the first row of this table that fits, reading top to bottom, EXCEPT: if a lookup is used, the type is LOOKUP even when other functions surround it.

## 2. Syntax
- A rule is one assignment: `TARGET_COLUMN = <expression>`. Comments follow `--`.
- Source columns are written as the bare source column name (`CUST_NM`), or `TABLE.COLUMN` when two tables are joined.
- Parameters start with a colon: `:BATCH_ID`, `:RUN_TS`, `:LAST_WM`, `:BUSINESS_DT`.
- Strings in single quotes. Dates as strings `'YYYYMMDD'` for formats, `DATE '2026-01-31'` for literals.
- Operators: `= <> < <= > >= AND OR NOT IN BETWEEN IS NULL IS NOT NULL || (concatenate)`.
- Every function returns NULL when any input is NULL, unless stated otherwise.
- Comparisons of text are case-sensitive. Use `LOWER()` or `UPPER()` explicitly when case must be ignored.
- No tool-specific names in the rule (no `IIF`, `DECODE`, `NVL`, `tMap`).

`HASH_ROW` rule: always list the columns in the STM rule in a fixed order and cast every column to text first. Use it for change detection only, never as a key.

## 4. Patterns to reuse (copy these shapes)
| Need | Rule |
|---|---|
| Trim and treat blank as NULL | `COL = NULLIF(TRIM(SRC), '')` |
| Code translation with default | `COL = COALESCE(LKP(REF_X, SRC -> target_value), 'UNKNOWN')` |
| Date from CHAR(8) with sentinels | `COL = CASE WHEN SRC IN ('00000000','99999999') THEN NULL WHEN IS_DATE(SRC,'YYYYMMDD') THEN TO_DATE(SRC,'YYYYMMDD') ELSE NULL END` |
| Timestamp to UTC, fixed offset (no daylight saving) | `COL = TS_SHIFT_MINUTES(SRC, -330)` -- IST = UTC+05:30 |
| Timestamp to UTC, zone with daylight saving | `COL = TS_TO_UTC(SRC, 'Europe/London')` |
| Flag to Y/N/U | `COL = CASE WHEN SRC IN ('Y','N') THEN SRC ELSE 'U' END` |
| Split email | `LOCAL = SUBSTR(A,1,INSTR_LAST(A,'@')-1)`, `DOMAIN = SUBSTR(A,INSTR_LAST(A,'@')+1)` |
| Surrogate key | `COL = NEXT_SEQUENCE(SEQ_DIM_X)` for new business keys only |
| Audit | `SRC_SYSTEM_CD = '<SOURCE>'`, `BATCH_ID = :BATCH_ID`, `LOAD_TS = :RUN_TS` |
| Number with scale | `COL = CAST(SRC AS DECIMAL(18,2))` -- never round unless the STM says so |

## 5. Bad vs good
| Bad (rejected by review) | Why | Good |
|---|---|---|
| `clean the date` | prose | `RECEIVED_DT = CASE WHEN IS_DATE(...) ...` |
| `TO_DATE(DOB_STR)` | no format, no guard | `... IS_DATE(DOB_STR,'YYYYMMDD') ...` |
| `NVL(X,0)` | Oracle-only name; defaults amounts to 0 | `COALESCE(X, ...)` only where the STM default says so |
| `IIF(a,b,c)` | Informatica-only | `CASE WHEN a THEN b ELSE c END` |
| `LOOKUP(...)` with no reference name | unclear | `LKP(REF_DIRECTION, DIR_CD -> target_value)` |
| `CUSTOMER_NAME = CUST_NM` plus "uppercase it" in Comments | rule and comment disagree | `CUSTOMER_NAME = UPPER(TRIM(CUST_NM))` |

## 6. Dialect notes (when the neutral rule is turned into SQL)
- Oracle stores the empty string `''` as NULL; SQL Server does not. A rule that uses `NULLIF(TRIM(x),'')` is correct on both.
- SQL Server `LEN` ignores trailing spaces; `DATALENGTH` counts bytes. For `nvarchar`, bytes = 2 x characters.
- `CHAR(n)` columns are space-padded: always `TRIM` before comparing or looking up.
- Integer division: `7/2` is 3 on SQL Server and 3.5 on Oracle. Cast to `DECIMAL` first.
- Date literal and string comparison use the session's NLS or language settings; always give the format explicitly.
